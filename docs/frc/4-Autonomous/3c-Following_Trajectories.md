# Following a trajectory

**Prerequisites:** [swerve and localization](../1-Basics/Modern_Drivetrain_Project.md), [motion profiles](../3-Closed_Loop_Control/5-Motion_Profiling.md). A path describes geometry; a trajectory adds time, velocity and acceleration. A follower compares a time-indexed target with an estimated pose and requests chassis motion. Its output is constrained by the drivetrain, available voltage, traction and the quality of its pose estimate; feedback does not guarantee exact tracking.

Team 1257's former historical differential-drive example repository is no longer publicly available. Study the [2026 drivetrain and autonomous case study](../../robots/2026-code.md) instead, then trace the [pinned 2026 Drive implementation](https://github.com/FRC1257/2026-Robot/blob/0c9a024dec1f58648d573ce26fcfd02639c5ca66/src/main/java/frc/robot/subsystems/drive/Drive.java). The two projects use different drivetrains and APIs. Follow [the guided swerve project](../1-Basics/Modern_Drivetrain_Project.md) for the simulation exercise and its limitations.

**Exercise:** in a configured simulator, start from a known pose and run a short, version-matched trajectory. Compare the target and measured pose over time; then repeat with an intentionally wrong starting heading. Explain the difference and verify cancellation stops the command. A growing error can have several causes, including a frame mismatch, incorrect module calibration, saturation or model error. Inspect those signals before drawing a conclusion. If no suitable simulation is available, trace the code and state that the trajectory has not been run.
