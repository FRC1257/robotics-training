# AprilTag walkthrough — 2026-11-11

The new `labs/vision.html` is an original seven-step explanation of capture, corner/ID detection, camera pose, robot pose, mounting error and latency. It has two navigation buttons. A camera-placement control appears only at step 5, latency at step 6, and timestamp handling at step 7. It is embedded in the camera-geometry lesson and linked from vision navigation, the lab index and the vision learning path. It supports the existing local theme, progress, sitemap and social-card generation.

The image is a constructed, cropped 640 × 400 pinhole frame using the existing, unmodified AprilRobotics tag36h11 ID 7 asset. See `research_sources/vision-media.json` and the included BSD notice. The corners and decoded identity are supplied analytically, not computed by an actual image detector. The black border is distinguished from the PNG's white margin. The scene assumes a 0.165 m black-border size and 900 px focal length; neither is a measured calibration or an asserted season-specific target specification.

The planar transform model reconstructs camera pose from a known tag and ideal camera-to-tag observation, then removes the configured robot-to-camera transform. The scene has fixed zero robot/camera yaw and equal camera/tag heights; it does not run general 3D PnP, model distortion or ambiguity, or execute robot Java. The pure transform functions also have rotated-frame unit coverage. Latency compensation advances exactly known constant 2 m/s field motion, which illustrates capture-time association rather than reproducing WPILib's estimator. Timestamp synchronization, retained history, measurement uncertainty and validity remain required in a real robot implementation.

Primary sources reviewed: [PhotonVision 2026.3.3 pose estimator](https://docs.photonvision.org/en/v2026.3.3/docs/programming/photonlib/robot-pose-estimator.html), [3D tracking](https://docs.photonvision.org/en/v2026.3.3/docs/apriltag-pipelines/3D-tracking.html), and [WPILib pose estimators](https://docs.wpilib.org/en/stable/docs/software/advanced-controls/state-space/state-space-pose-estimators.html). These support the pipeline and timestamp requirements; all example coordinates, error values and projected corners come from the explicitly assumed teaching model.

Verification covers projection/depth, transform inversion including rotated mounts, physical/configured mount separation, delay and timestamp behavior, bounded inputs, all seven UI stages, contextual controls, keyboard navigation, desktop/mobile screenshots, themes and embedding. Browser screenshots must be visually reviewed before publication. No physical camera or robot test is claimed.
